Glassboard now streams collaboration through WebSockets instead of waiting for two-second polling.

- See strokes **while someone draws**, and elements while they move or resize them.
- Live text previews, collaborator cursors and a connection/participant indicator.
- Incremental stroke packets, frame batching and cached pen bounds reduce unnecessary work.
- Saved changes push as object deltas. Save uploads include changed objects only.
- Automatic reconnect, revision resync, heartbeats and bounded send queues.
- Two-second polling remains only as a fallback when WebSockets are unavailable.
- Existing merge/conflict recovery and persistent storage are retained.
- Still one container on port 3000; Traefik routes WebSockets on `/api/live` using the existing hostname.

## Upgrade

Set `GLASSBOARD_VERSION=1.1.0` in your existing `.env`, then:

```sh
docker compose pull && docker compose up -d
```

**Reload all open browser tabs.** No board/image migration or additional service is required. The existing persistent data volume must be kept.

The registry image `ghcr.io/progries/glassboard:1.1.0` supports linux/amd64 and linux/arm64. A linux/amd64 Docker archive, source ZIP, SHA256SUMS.txt and container digest are attached. The Traefik deployment guide is `docs/deployment-traefik.md`.

Live preview timing depends on your network; unfinished previews are temporary, and become durable once saved. Simultaneous conflicting changes to the same object still create a recovery board rather than silently discarding edits.
